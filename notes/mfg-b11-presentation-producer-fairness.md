## Source mechanism and chosen repair
The completed presenter uses a highest-priority worker. `PresentCompletedFrame` used to compose only while the next completed frame was sufficiently far in the future, or when deque empty. Late heads could bypass an unavailable frame-latency permit; even DXGI DO_NOT_WAIT did not prevent full-refresh-duration calls on the test PC. The receiver additionally prioritized the due head before evaluating B08 bank recovery. With repeated slow presents this is a plausible starvation loop, not evidence of weak GPU or explicit reset. B11 provides bounded normal producer opportunities in the existing lock/timer architecture instead of waiting for queue empty. No unlocking around DXGI/Immediate Context, no new thread, synchronization object, GPU pass or busy wait, no change to Present(1) flags, no changes to PTS or original/synthetic ordering.

- `CompletedPresentFairness` in `Source/Edition/CompletedBufferPolicy.h`: a successful present taking >= half the current refresh period earns one source-admission credit. Slow episode remains active until four consecutive fast successful presents, an unsuccessful non-busy present, an ineligible successful path, or timeline clear. Busy retry doesn't grant credit. Refresh must be valid (1–1000 ms). Threshold and four-frame hysteresis are chosen engineering defaults, not measured optimal values. Credit consumed on successful completed-target acquisition, even if downstream receive subsequently rejects sample. No counter depends on waterline.
- `CompletedFairProducerCanvas`: restrict exceptional path to running fixed processing canvas / asynchronous MFG, same head and batch canvas/format, no startup/failed state. No MFG effective generation and no batches => inactive; ordinary playback/bypass unchanged. Preserve B09 and existing overlap checks.
- `TryServiceCompletedProducer`: after slow successful Present and ownership recycling, offer ONE normal `PrepareCompletedBatch(stream)` turn under RendererLock; also can service on unavailable permit in active episode. Fresh StreamTime, valid completed fence, conservative 8 outstanding-fence and 256 queue slots including candidate phases, existing memory budget with full generated footprint, state/flush/cancellation check. Pending NGX work uses normal return false. No force argument, no new synthetic discard rule. Ordinary PrepareCompletedBatch keeps its existing deadline/budget/drop behavior, which can still drop truly late or invalid synthetic frames. This is a scheduling opportunity, not proof of bounded driver time or mandatory successful composition. B08 original-first emergency remains unmodified.
- In `PresentCompletedFrame`, when actual waitable permit unavailable during slow episode, service normal batch or return false (existing 1 ms unlocked worker retry) even for due head, until head is one refresh late; then retain old nonblocking fallback to protect stalled/occluded DWM and non-waitable paths. Outside episode, original permit behavior. The one-refresh boundary is a deliberate safety limit, not a newly inserted delay for every frame.
- In `CompletedAdmissionBlock`, only initial head deadline guard may open for a ready fixed head less than one refresh late with unconsumed credit. Actual lookahead, device, queue, fence, overlap, bank, budget checks remain unchanged. A second overlap deadline may still reject for other processing routes, by design; new normal compose turns can retire the blocking batches. No queue-empty shortcut expansion. A source which doesn't successfully acquire target cannot consume credit; it cannot use it to bypass later checks.
- `RendererSourceState.inc`/`VideoRendererScheduling.cpp`: Receive publishes actual renderer-lock waiter between InterfaceLock acquisition and RendererLock acquisition (serialized by InterfaceLock). Existing lock order/critical sections and cancellation unchanged. On slow successful present, offer a single absolute 1 ms QPC source turn after normal compose; `NextCompletedFrame` may defer its next work on existing timer only if a real input waiter is still present, eligible fixed ready head within one refresh, credit available. No waiting while holding lock, no extension on wake, no delay when no waiter, no artificial present retry counter increment. Scheduler/OS can overshoot timer; source acquisition not guaranteed by portable model. `ClearCompletedFrames` resets all fairness state, no waiting on it during Stop/Seek/Flush.
- Trace `completed_fair_compose`: normal service completed; queue depth and elapsed duration, E_FAIL if completed pipeline marked failed. `completed_fair_deadline_open`: one head-gate opportunity, NOT proof of subsequent admission. `completed_fair_source_turn`: existing timer deadline offered to actual waiter, QPC in due_qpc. `completed_receive_lock_wait`: duration of source RendererLock acquisition (after InterfaceLock), only opt-in trace and >=1 ms. Existing B10 diagnosis and CSV schema unchanged.
