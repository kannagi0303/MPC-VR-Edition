# MFG-B08 — Normal-first resize recovery (2026-11-24 17:28 +08:00)

## Baseline and user report
Exact local VE-08 incremental overlay, not a new remote checkout. User reports the previous delayed buffer drain to zero after resizing is fixed. After startup around 5 s one generated-frame skip is observed; after four/five repeated window resizes MFG may skip generated frames for about 3–4 s then recover. User wants recovery to be nearly imperceptible, without sacrificing original frames or reviving delayed buffer depletion. The startup skip has not been attributed to any specific cause; it may or may not be related to B08 (e.g. an initial real resize can arm it). No actual trace was supplied. Do not call the cause proven from static source.

## Actual source findings and changes
- Old `CompletedAdmissionBlock` in `DX11VideoProcessorCompletedFrames.cpp` invoked `PrepareCompletedBatch(stream, true)` whenever the resize arm was set, async producer was active and overlap reported bank/slot pressure. This bypassed the normal wait for future, pending synthetic phases even if the original and the ready queue had substantial time left. A real resize arms the flag, ClearCompletedFrames clears it; it is not an expiring timer.
- `[MFG-B08 | 2026-11-24 17:28 +08:00]` in `Source/Edition/CompletedBufferPolicy.h`: normal compose first via `PrepareCompletedBatch(stream, false)`. If it returns true, recheck the exact existing queue limit, GPU fence, bank, and memory admission. If false (future synthetic phase still pending), check actual contiguous ready lead (`GetCompletedBufferTime(stream).ready`). At >= existing `CompletedStartupLead` (250 ms), defer to the existing 2 ms cancellable admission retry outside RendererLock; below that reserve, allow the old original-priority escape. The reserve is a provisional engineering threshold, not a new queue target, not a sleep or startup requirement. No change to normal non-resize or seek admission. No additional GPU pass or new thread.
- Retain the resize arm as a dormant safety net until the existing timeline reset. Do NOT clear it merely after 500 ms or one successful admission: the previously reported regression was a delayed decline after all geometry interaction ceased. Each attempt independently gates forced retirement; when pressure resolves or ready reserve recovers, no forced mode persists. This is intentionally different from prematurely expiring the entire safety net.
- Actual early pending synthetic drops from forced retirement now get `completed_drop_ngx_resize_recovery` in the existing opt-in cadence trace, rather than being conflated with normal original deadline drops. An accumulated per-completed-timeline counter `m_completedResizeEarlyDrops` appears as `MFG resize N early drops` in existing detailed Statistics only when nonzero. Counter resets with ClearCompletedFrames. Late/present/budget drops retain their behavior, original frame protection and original counts unchanged. No compulsory logging or new UI switches.
- No changes to `CompletedOverlapBlock`, ordinary `PrepareCompletedBatch` deadline logic, fence ownership, bank selection/NGX Session, `PresentCompletedFrame`, `CompletedSubmitLead`, `CompletedGeometryChanging`, pending resize/coalescing, buffer capacity/target, scheduler, VE-08, SR, depth, color math or fast exit. Original startup/seek paths retain their existing semantics. No new delays or retry loops under the lock.
