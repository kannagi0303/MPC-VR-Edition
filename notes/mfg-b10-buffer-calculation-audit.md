## Source audit
- `GetCompletedBufferTime`: walks the deque in insertion order. `ready = ready && increasing && frame.fence <= time.fence`. Strict increasing `due`; first tie/reversal or unsignaled fence excludes the entire suffix even if later frames are signaled. Queued uses maximum due independently, excluding outstanding batches. `ready` and `queued` are clamped at zero by initialization. `BufferPercent` floors to integer; 0% includes <20 ms at the 2 s target (startup target 250 ms). No change to either function.
- A fixed first invalid pair can pin the reported ready endpoint while StreamTime increases; once predecessor exits the deque, later frames can count again **without deque emptying**. `QueueCompletedFrame` assigns increasing fences on one timeline; ordinarily later fences cannot finish ahead of an earlier queued fence. Timestamp order is therefore a particularly useful hypothesis when signaled suffix remains. Generated phase enqueue checks tail due, but the original phase is enqueued without that same explicit comparison; this is a possible source path, not evidence it occurs on the user's PC. `due` is presentation time, not necessarily media PTS. Don't reorder/drop originals or relax the prefix policy as a speculative fix.
- DXGI `GetFrameStatistics` sampled about once a second in DrawStats. It may fail or require a new baseline, reject reversed counts, reject rate > refresh*1.2+1 or unknown refresh. Its availability flag is advisory only. Buffer stats sampled at ~250 ms during stats drawing; may exclude the current popped present frame, or be delayed until next draw. No shared math between the two. DXGI failure/recovery can reflect shared presentation/resize changes, not necessarily a causal link. A failed sample also requires a later baseline and another valid sample; do not demand exact simultaneous GUI changes.
- `CompletedAdmissionBlock` contains empty-queue exception, but the counterexample shows no actual empty queue is needed. The user reports a refill rather than instantaneous jump: our injected tie test does not reproduce refill speed and is not a real scheduling simulation. Separate actual ready depletion, cutoff, clock, and policy feedback in real trace.

### CSV schema mapping (existing columns reused by event)
- `buffer_audit`: qpc=sample time; source_pts_100ns=ready end due; stream_time_100ns=stream; serial=completed fence; phase=ready frame count; effective_multiplier=queued frame count; ngx_generated=signaled frame count; due_qpc=queued end due **in 100 ns, not QPC**; precomposed=geometry changing; presentation_time_100ns=signaled end due; completed_frames/batches=counts; completed_tail_due_100ns=maximum queued due (audit only); submit_lead_before/after_ms=same snapshot pacing estimate; submit_pacing_samples=count. -1 denotes no endpoint, UINT64_MAX invalid fence. Use counts to disambiguate.
- `buffer_cutoff_*`: qpc same as audit; source_pts_100ns=preceding due; serial=cutoff frame fence; phase=zero-based index; effective_multiplier=non-increasing pair count; ngx_generated=displayed percentage; due_qpc=cutoff due **in 100 ns**; precomposed=DXGI rate currently displayed as valid (last stats sample); presentation_time_100ns=waterline target. None/no_fence use sentinel fields. First failure only, later order inversions counted separately.
- `mfg_dxgi_status_*`: qpc=sample tick; serial=current PresentCount, phase=previous count, effective_multiplier=PresentRefreshCount, ngx_generated=SyncRefreshCount, due_qpc=SyncQPCTime, precomposed=had baseline, result_hresult=actual call result or E_FAIL when unsupported, duration_qpc=rate window. rate_reset event marks reset at next statistics call. Existing `mfg_dxgi_sample` success records preserved.
- Existing `completed_enqueue`, `completed_present`, `completed_present_busy`, wait/admission events, `completed_clear`, resize commits and drops allow correlation. Stats calls not necessarily aligned to same present; use common QPC timestamps. No direct proof if samples missing.
