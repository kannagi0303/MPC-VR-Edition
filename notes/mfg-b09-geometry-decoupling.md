# MFG-B09 — Geometry-independent producer admission (2026-11-24 17:51 +08:00)

## Baseline and problem
Exact conversation-delivered `MFG-B08-Normal-First-Recovery` overlay, not a new GitHub checkout. User reports extremely dense alternating resize can still drain the Video Buffer to zero; prior fixes made the issue harder to trigger, not conclusively solved. The old delayed drain after all resizing stops remains a regression condition. The startup skip near 5 s remains unattributed. The goal is to stop coupling output geometry to video production, not to increase early synthetic retirement. Keep original frames, seek/flush cancellation, fast shutdown and VE-08 unchanged.

## Verified source findings
- `PrepareCompletedTarget()` already creates `videoOnly` fixed-size targets when `m_processingSize.cx > 0`. `PrepareEditionRender`/`RenderEditionVideo` permit those detached paths during pending resize. `PrepareCompletedBatch` uses the stored target rectangle and texture, not the new window rectangle. Pending batches protect their NGX bank until normal compose/retirement.
- Nevertheless `CompletedOverlapBlock()` rejected every overlap while `CompletedGeometryChanging()` was true (pending resize or <500 ms from the last geometry event). Repeated changes extend this interval. This disables legitimate pipelining even when neither batch input nor output canvas changed. It also returns `completed_wait_batch` rather than bank/slot pressure, so B08 cannot address this case. The restriction is proven by source; its contribution to real-world underflow is not measured yet.
- `NextCompletedFrame()` committed resize before considering the next presentation deadline; `PresentCompletedVideo()` also attempted a resize directly on the due-frame path. Both can incur driver/texture/OSD work under the existing renderer lock. The actual driver cost remains unknown.

## Changes (only two production .cpp files)
- In `CompletedOverlapBlock`, leave startup/original-prime/no-MFG, budget, slot, bank reservation, ownership, fence, deadline and memory checks intact. During geometry transition allow the **same normal overlap decision** only if every pending batch has a video-only target covering the current fixed `ProcessingRect()`, with matching nonzero dimensions and swapchain format. Legacy/window-sized, mixed or mismatched batches keep blocking (`completed_wait_geometry_batch` trace reason). No new bank, capacity, timeout, or bypass of existing bank/fence checks. No input processing route is changed.
- In `NextCompletedFrame`, keep the existing 140 ms coalescing interval, give an imminent completed queue head priority (existing submit lead + 2 ms admission margin), and commit when a gap is available or there is no head/clock is unavailable. This is ordering, not a guarantee that a driver call finishes within the gap. Scheduled `PresentCompletedVideo` no longer independently commits resize; it uses existing pending-geometry mapping. External/paused redraw and geometry-dependent target paths keep existing behavior. The worker still handles pending resize even with an empty queue. No extra waiting or thread. Keep existing presentation estimator reset, 500 ms pre-draw/cheap-scaling guard, B08 normal-first + emergency reserve, buffer goals, and renderer lock scopes untouched.
- Existing opt-in cadence CSV `window_resize_commit` now records actual CPU duration including driver and resource work; failures emit `window_resize_commit_failed` with HRESULT/duration. CSV schema unchanged. No logging dependency for normal playback.

## Validation actually executed
- `python build-support/edition/tests/ResizeGeometryAdmission.py` extracts the actual production overlap method and commit predicate, compiles portable stubs and uses actual `Mfg/BankSelection.h`. 100,000 random conditions: 6,648 admits and 93,352 rejects; exact equality with/without geometry transition for a valid fixed canvas, including bank ownership/producer and reader fence, slot, startup, budget, and deadline checks. Mixed/window-sized/wrong rect/dimensions/format/zero canvas remain blocked. 500 eligible overlap opportunities during a synthetic 8 s geometry guard all remain admitted. Tests include exact 140 ms and submit-lead+2 ms commit boundaries, empty queue and invalid clock. ASan/UBSan pass. This is an admission-policy test, not a measured throughput or GPU timing simulation.
- Portable existing B08 reserve/retirement, VE-08 startup/fade, SVDLUT FP32 input, B2.1 and extracted actual B2.2 shader math tests pass. Source diff confirms no changes to `PrepareCompletedBatch`, `CompletedSubmitLead`, `CompletedGeometryChanging`, `GetCompletedBufferTime`, MFG bank selection/session, VE or cancel/stop paths.
- Linux environment has no MSBuild/Windows Direct3D runtime; x64 Release, Windows page/upstream-boundary scripts, actual ResizeBuffers/NGX playback and user resize/seek acceptance remain unverified. No commit/push/deployment.

## Acceptance and follow-up
Use same clip/settings and compare B08 against B09: first 15 s (including prior ~5 s skip), dense alternating resize including several seconds of continuous toggling, stop all interaction and observe Ready/Queued Video Buffer and MFG cadence at least 60 s. No delayed drain, no sustained generation gaps, no extra original drops, no slower seek/close. Check VE off/on, SR off/on, MFG bypass, genuine display mode changes, paused resize. B08 early-drop counter stays available. Do not declare root cause solved solely from these portable tests. If depletion persists, compare existing admission wait durations (`completed_wait_*`), `completed_produce`, `completed_compose`, `completed_swap`, `window_resize_commit` duration, Ready vs Queued and early-drop count; if real DXGI/Flush/lock stalls dominate, pursue measured presentation resource isolation rather than further weakening bank admission or changing watermarks. No unconditional removal of geometry guards or independent D3D11 context/thread changes without a reviewed ownership contract.
