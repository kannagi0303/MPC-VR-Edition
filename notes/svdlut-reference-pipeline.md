## Root causes fixed, not visual heuristics

1. The shared native `m_pSamplerLinear` is `D3D11_FILTER_MIN_POINT_MAG_LINEAR_MIP_POINT` (DX11VideoProcessor.cpp:1646). Calling TextureCopyRect(..., true) did NOT implement Bilinear for downsampling from video to 256x256. This is separate from the earlier RGBA8 thumbnail rounding issue. The shared `RenderSvdLutThumbnail` now uses a dedicated FP32 Load/lerp shader with half-pixel centers (`align_corners=False`), bounds clamped to the sampled rectangle, not the whole containing surface. Uses same existing 256x256 draw, no extra pass. A, synchronous RAW B and async Temporal B share it. All staging/thumbnail textures now RGBA32F; ReadPlanar, scene signature and B2.1 512 sample locations read the same RGB code values. Model inputs remain NCHW [1,3,256,256]. Source image values are clamped to [0,1] as previous UNORM texture did. No extra gamma curve: DXGI RGB_FULL_G22_NONE_P709 is defined as intended sRGB (https://learn.microsoft.com/en-us/windows/win32/api/dxgicommon/ne-dxgicommon-dxgi_color_space_type). The active swapchain tag is not proof of every earlier conversion; see open issues.
2. Model loader validates external tensor exact storage shape and contiguous strides (singleton axes irrelevant), not merely byte count. Real graph directly parsed with project vendored FlatBuffers header and verifier: image [1,3,256,256] 786432 B; lut_planes [1,9,33,33] 39204 B; lut_mix [1,1,1,12] 48 B; grid_planes [1,1,1,5202] 20808 B; grid_mix [1,1,1,24] 96 B. All five have implicit contiguous strides. Model graph itself not modified. 27 operators / 38 constants / 160478 FP32 constants; no non-finite weights; 5 conv, 4 instance normalization, 5 LeakyReLU, 1 pooling, 11 GEMM, 1 multiply; CPU reconstruction from real graph weights passed shape and finite-output checks. Original checkpoint equality remains unproven.
3. Native ordered dithering previously happened upstream of SVDLUT where enabled; grade then wrote fractional codes to UNORM without a final dither. Shared output wrapper now reuses the existing native 32x32 threshold resource at t4, after all A/B grade math (including B2.1/B2.2/R1/M1 and fused P1). Uses existing `m_bUseDither`; 255 for 8-bit and 1023 for 10-bit, no extra fullscreen pass. Integer codes (incl. black/white) preserved; outside picture returns as before. Standalone P1 unchanged (Q=0); no dithering for disabled setting/unsupported format/missing resource. Resource unbound after draw; no new GPU texture, alpha unchanged. This corrects the SVDLUT UNORM write boundary, not every prior quantization. If a legacy path resizes a graded intermediate afterwards, that is still a subsequent quantization boundary. Dither is not intended to repair model clipping or pre-existing banding.

## Open end-to-end boundaries — do not claim fully verified

- A's native D3D11 VP capture still intentionally converts/scales directly to a 256x256 `nativeThumbnail` in VP's configured RGB format before the shared shader. VP filter and precision are not guaranteed identical to PyTorch. Correcting this requires using an already available native-size RGB image, or paying for full-size VP conversion and checking VSR/VP temporal side effects. The patch avoids enlarging the VP pass or changing A scheduling. A's early capture and B's completed picture capture are distinct intentional policies. RAW B on same original RGB crop is the appropriate model reference.
- Prior RGB representation can be 8-bit before SVDLUT (especially MFG BGRA8, VSR, legacy backbuffer and completed resize fallback). Dither after grade cannot recover lost source levels. Full high-precision pipeline redesign across MFG/SR/VP/presenter and scaler boundaries is not covered. Exact source/display transfer/CSC, range and HDR bypass across all video routes are not proven solely by swapchain color-space tag. No blind gamma transforms.
- Need compare graph constants/reconstruction against official checkpoint, actual DirectML output tensors vs reference CPU/PyTorch on Windows, and physical GPU shader outputs vs CPU (including texture sampler fractional precision and crop/letterbox edges). Official integer-divided spatial edge behavior retained per prior RF1 math verification. No changes to PackParameters, regularity, scene policy, B2 gains, temporal regression, MFG original protection, fast exit, SR, ZipDepth, UI. Keep P6 disabled.
- True whole-pipeline correctness requires quantitative acceptance across source precision, display precision, and temporal frame routes, rather than relying on Dither or compensating B2.1. Next architecture review should map where quantization is unavoidable due to NGX versus optional in renderer. Do not assert previous banding is fixed from offline tests alone.
